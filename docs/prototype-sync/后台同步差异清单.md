# 产投华创后台原型同步差异清单

核对日期：2026年10月26日  
用途：为产品与测试评审提供本轮修改范围、现存差异和后续确认事项。  
适用成果：本目录下的 `cthc-后台原型同步` DEMO 工作副本。

## 本轮结论与使用范围

本轮已补齐后台业务导航，新增经纪人、子商户、交接清单模板、房源住建和再次导出审批入口，并扩展资产配置。**这些修改尚不等于全部后台功能与开发成果完成同步。** 合同、订单、租客档案、转租等核心模块仍有下文列出的实质差异。

- 功能与字段依据开发测试后台的实际可见页面核对；视觉继续采用原 DEMO 的蓝色顶栏、白色侧栏、表格与表单样式。
- 本次只处理后台。移动端与红框菜单排除：系统监控、系统工具，以及系统管理下的菜单管理、岗位管理、字典管理、参数设置、通知公告、日志管理。
- 记账本按用户明确要求弃用：移除菜单、角色菜单项和原业务页面；旧地址仅显示停用说明，不跳转或复活为临时收款。
- 新增经纪人、子商户、交接模板均使用虚构演示资料，只保存在当前浏览器。房源住建使用本地 DEMO 房源与浏览器内的补充资料，不向住建平台发起真实核验或上架。
- 未把开发站的真实姓名、手机号、证件号码、业务记录或附件复制到本交付文档及新增演示样例。
- 本清单记录已观察到的页面与代码差异；未验证的接口规则、权限、异常分支与外部系统回执不视为已确认需求。

## 建议优先落地的八项

1. **明确合同新增字段与导出口径。** 模板筛选、交互筛选和列、用户来源列及 CSV 已补；下一步提供租户交互、用户来源的真实字段与枚举，确认业主导出格式。删除先确认允许状态及账单/附件影响，避免混淆退租、作废与删除。
2. **确认租客补充资料的回写与关联规则。** 详情、编辑、关联状态位置、精确查询和脱敏 CSV 已补；下一步提供关联状态真实字段、完整证件检索接口与人员资料字典，明确手机号/证件变化对订单、合同及实名的影响。
3. **对齐订单实名接口与业务约束。** 列表已展示明确的人脸核验记录或“待核对”；下一步核实开发统一实名状态与审核、签约的关系，不能仅凭证件已填推导已实名。
4. **按开发重核转租日期、原因和材料配置。** 独立筛选、模板关联及已有初审记录已补；继续提供日期与原因真实字段，明确资料项重载的来源、效果和失败表现。
5. **完成交接模板到合同附件五的可演示关联。** 明确选用入口、按序带入、合同内独立修改、历史快照及停用影响；保持分类、单位等规则与实际开发表单一致。
6. **补齐财务可核对字段与状态边界。** 优先处理再次导出审批的申请/收据/申请人字段、已拆列的逾期未付金额真实响应，以及核销超额转预收后的流水关系，避免只能看按钮却不能核对金额去向。
7. **统一资产、子商户、住建的状态与校验来源。** 明确哪些是后台演示状态、哪些来自服务端；补小数价格存储、停用子商户、门店范围、资产同步覆写与住建回执规则。评审阶段保留清晰的演示标签。
8. **恢复临时收款页面后再定稿该模块。** 当前 404 是直接阻塞，应由开发先修复或提供可访问成果，再核对新流程；继续保持记账本停用，不用旧功能替代未知需求。

## 验证与评审约定

- 本轮后台代码已通过 TypeScript 编译与 Vite 构建；该结果证明可以构建，不证明各业务流程已与开发环境一致。
- 新增通用页面已进行定向代码检查，包含必填/唯一性提示、空态、分页、批量选择、弹窗键盘操作和存储失败提示；最终浏览器走查结果以实际评审记录为准。
- 开发环境只做页面查看和表单观察，未通过提交真实合同、核销、支付、删除或住建上报来验证后端效果。
- 评审时分别标记“已补充可演示”“保留旧能力待复核”“开发页面不可访问”“业务规则待确认”，不要把“菜单已出现”记为“功能已验收”。
- Axure 的页面图、说明、状态与演示入口也需要逐项核对。本清单是交付伴随说明，**不能单独作为 `.rp` 已完成修改或全部需求已同步的证明**。
